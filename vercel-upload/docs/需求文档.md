# 讲稿工坊 · 网站需求说明

> 一句话定位：**把 PPT 变成一份能直接念的演讲稿**。用户上传 `.pptx`，选择一种演讲风格，系统按页生成开场白、逐页讲稿、过渡与结尾，并支持在线修改、全屏提词和导出。
>
> 技术栈：前端 Vue 3 + Vite ｜ 后端 FastAPI ｜ 数据库 MySQL 8 ｜ 大模型（OpenAI 兼容接口，可替换为 DeepSeek / 通义 / Moonshot 等）

---

## 1. 项目背景与目标

**问题**：多数人做完 PPT 之后，仍然不知道怎么讲——不知道开场说什么、每页讲多久、页与页之间怎么衔接，最后只能照着幻灯片念字。

**目标**：把「PPT → 演讲稿」这一步自动化，并且交付的必须是**口语化、可直接照读**的稿子，而不是要点摘要。用户只需要做三件事：上传、选风格、拿到稿子。

**衡量指标（课程/答辩可用）**

| 指标 | 目标值 |
| --- | --- |
| 上传到生成出稿 | ≤ 60 秒（模板引擎 < 1 秒，大模型 20–60 秒） |
| 单份 PPT 解析 | 6–80 页，单文件 ≤ 30MB |
| 讲稿字数与时长误差 | 与目标时长偏差 ≤ 20% |
| 支持风格 | 8 种 |
| 页面首屏加载 | ≤ 2 秒（本地） |

## 4. 非功能需求

| 类别 | 要求 |
| --- | --- |
| 性能 | 接口 P95 < 300ms（不含大模型）；生成接口超时 180s；首页 ≤ 2s |
| 并发 | 单机 Uvicorn 4 worker 支撑 50 并发（课程规模） |
| 安全 | 密码加盐哈希；令牌 HMAC 签名；上传类型/大小白名单；SQL 全参数化（ORM）；用户数据按 user_id 隔离；CORS 白名单 |
| 兼容 | Chrome / Edge 最新版；≥1280px 宽屏优先，1080px 以下单列自适应 |
| 可用性 | 大模型不可用时自动降级到模板引擎，功能不中断 |
| 可维护 | 前后端分离；风格库集中在 `services/styles.py`；配置全部走环境变量 |
| 数据 | MySQL 8 / utf8mb4；本地无 MySQL 时自动回退 SQLite 便于演示 |
| 隐私 | 上传文件仅服务本用户；不对外提供下载 |

## 5. 技术架构

```
浏览器 (Vue 3 + Vue Router + Vite)
   │  /api/*  (JSON, Bearer Token)
   ▼
FastAPI (Uvicorn)
   ├── routers: auth / presentations / scripts / meta
   ├── services: ppt_parser(python-pptx) / generator(LLM+模板) / exporter(Word, MD)
   └── SQLAlchemy ORM
   ▼
MySQL 8 (utf8mb4)   ←→   OpenAI 兼容大模型接口
```

**为什么这样选**

- **Vue 3 + Vite**：组合式 API 写页面状态简单，Vite 冷启动秒级，适合演示。
- **FastAPI**：类型化请求响应、自动 OpenAPI 文档（`/api/docs`），异步调用大模型不阻塞。
- **MySQL**：结构化存储文稿与讲稿，JSON 字段存每页要点与整份讲稿，查询方便。
- **SQLite 回退**：只为「没装 MySQL 的电脑也能一键跑起来」，生产仍以 MySQL 为准。

## 8. 页面结构

| 路由 | 页面 | 主要内容 |
| --- | --- | --- |
| `/` | 首页 | 价值主张、拖拽上传、最近文稿、风格墙、三步流程 |
| `/login` | 登录 / 注册 | 双栏，左侧品牌文案，右侧表单 + 体验账号入口 |
| `/app/:id` | 工作台 | 三栏：幻灯片目录 / 讲稿正文（可编辑）/ 生成设置面板 |
| `/present/:id` | 演讲模式 | 全屏深色提词、计时器、进度条、下一页预览 |
| `/history` | 我的讲稿 | 讲稿与演示文稿两个页签，支持编辑、演讲、导出、删除 |

**关键交互**

1. 首页拖入 PPT → 自动解析 → 直接进入工作台；
2. 工作台右侧选风格、拖时长 → 「生成讲稿」→ 正文区出现开场白与逐页讲稿；
3. 点击任意段落直接修改，失焦即保存；
4. 「进入演讲模式」→ 全屏提词，方向键翻页，P 暂停，Esc 退出；
5. 「导出 Word / Markdown」下载成稿。

## 9. 验收标准（可逐条演示）

1. 未登录访问 `/app/1` 会跳转登录；登录后回到原页面。
2. 上传一份真实 `.pptx`，页数与标题和原文件一致，要点无乱码。
3. 同一份 PPT 用「正式严谨」与「轻松幽默」生成，语气明显不同。
4. 8 分钟时长生成的讲稿字数在 1500–2100 字之间，每页有建议用时。
5. 修改某页讲稿并刷新页面，修改内容仍在。
6. 演讲模式下方向键可翻页，计时器走动，Esc 可退出。
7. 导出的 Word 用 Office 打开不乱码，段落分页清晰。
8. 停掉大模型 Key 后仍能生成可用讲稿（模板引擎），页面标注「模板引擎」。
9. 删除文稿后，其讲稿一并消失，列表刷新正确。
10. 数据库切换到 MySQL 后，以上流程全部可用。

## 11. 风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| 大模型接口超时 / 限流 | 无法出稿 | 自动降级模板引擎，前端明确标注当前引擎 |
| 大模型返回非 JSON | 解析失败 | 提取首尾大括号解析，失败即降级 |
| 老格式 `.ppt` 无法解析 | 用户困惑 | 上传处直接提示另存为 `.pptx` |
| 讲稿长度不达标 | 现场超时/冷场 | 按语速换算目标字数，逐页分配并给出建议用时 |
| 上传文件过大 | 内存压力 | 30MB 上限 + 类型白名单，流式写盘 |
| 无 MySQL 环境 | 无法运行 | 启动时探测，失败自动回退 SQLite（仅演示） |
